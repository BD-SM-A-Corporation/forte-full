# Forte — интерфейс локального видеоанализа

Полный запуск обоих репозиториев с нуля, загрузка модели, NVIDIA/CDI,
проверка API, перезапуск и перенос на другую машину описаны в
[инструкции backend](../backend/README.md#запуск-проекта-с-нуля-и-передача-другому-разработчику).
Репозитории должны лежать рядом как `backend/` и `front/`.

Требуется Node.js 20.9+ и Bun 1.4.2 (`packageManager` в `package.json`). Из каталога `front`:

```bash
test -f .env.local || cp .env.example .env.local
# Заполните BACKEND_API_KEY тем же значением, что API_KEY в backend/.env
# BACKEND_API_URL — адрес FastAPI, доступный серверу Next.js
bun install --frozen-lockfile
bun dev
```

Интерфейс: http://localhost:3000. Сервер и worker запускаются по инструкции в `../backend/README.md`.
Для production: `bun run build`, затем `bun start`.
При переходе с разработки сначала остановите `bun dev`; не собирайте приложение
в `.next` работающего dev-сервера. После изменения `.env.local` перезапустите Next.js.
Backend Compose не собирает frontend из этого репозитория. `bun start` нужно
держать запущенным отдельно; постоянный запуск после перезагрузки хоста требует
менеджера процессов. `BACKEND_API_URL=http://127.0.0.1:8000` подходит для Next.js
на хосте; внутри контейнера задайте доступный из него адрес API.

Браузер отправляет MOV в `/api/backend/analyze`. Next.js передаёт файл потоком
на FastAPI и добавляет серверный `X-API-Key`. Ключ не попадает в клиентский bundle.
Прокси интерфейса публичен: при публикации ограничьте доступ к UI/прокси средствами
внутреннего контура или reverse proxy, если этого требует окружение.
Жюри получает непосредственно адрес FastAPI `/api/v1` и отдельный ключ доступа.
Настройте reverse proxy на приём файлов до 512 МБ и достаточное время загрузки.
Не размещайте видео-прокси на платформе с меньшим лимитом тела запроса.

UI опрашивает статус последовательно каждые 1,5 секунды, обрабатывает `done` и
`failed`, ограничивает ожидание пятью минутами и никогда не заменяет ошибку
демонстрационным результатом. Все 1–3 JPEG каждого события доступны в галерее.
Нормативные ссылки берутся из дополнительного `/jobs/{id}/details`.
Таймлайн загружает `observations` из этого же ответа для всех завершённых задач,
включая результаты без совпадений с правилами. Наведение на шкалу показывает все
наблюдения в выбранной точке; наведение, фокус или нажатие на маркер открывает
группу близких событий. Панель сохраняет исходный текст модели без перевода,
самооценку, неопределённости и таймкоды опорных кадров. Нажатие на таймкод
перемещает запись; Escape закрывает описание. Голубые отметки — наблюдения,
розовые — предварительные совпадения с правилами. Группировка не удаляет события.
Длительность шкалы берётся из метрик анализа, в том числе на странице сохранённой
задачи без исходного видео. Ошибка загрузки подробностей показана отдельно от
пустого списка наблюдений. Повторный анализ для просмотра сохранённого текста не нужен.
Индекс уверенности в действии берётся из `violations[].confidence` (0–1) и
показывается в шкале 0–100. Для старых ответов используется значение из `/details`.
Отсутствующая оценка отображается как «не предоставлен», а не 0. Индекс является
самооценкой модели, а не вероятностью нарушения. Неопределённости показаны в карточке.
Каждый результат предварительный и ожидает решения человека, даже без совпадений
с правилами. Экспорт JSON сохраняет `assessment`, индекс и его тип вместе с
совместимым устаревшим полем `verdict`. Исходное видео доступно в плеере только в текущей
сессии загрузки: API не предоставляет URL для воспроизведения исходника.
Браузерная поддержка кодека MOV зависит от браузера; JPEG-доказательства доступны независимо.

Страница «Правила и методика» запрашивает действующий реестр через
`/api/backend/rules` → `/api/v1/rules`. Она показывает источники, пункты, даты сверки,
условия применимости и отличие проверок от контекста для человека. Ошибка связи
не отображается как пустой реестр. Сейчас включены 11 записей по постановлениям
НБРК №231 и №14: четыре проверки признаков и семь контекстных оснований.
Для реального анализа также нужны Redis,
запущенный worker и локальные веса Qwen2.5-VL. Интернет для обработки не нужен;
интерфейс использует системные шрифты без загрузки Google Fonts.

Интерфейс объединяет светлый корпоративный дизайн, логотип Forte и переключатель
языков RU/KZ/EN с реальным API анализа. Выберите MOV, проверьте предпросмотр
и нажмите «Начать анализ». Плеер, таймлайн и доказательства находятся слева,
статус и события — справа. Новый анализ отменяет ожидание предыдущего результата
в браузере; уже принятую задачу сервер продолжает обрабатывать.
Страницы `/jobs/{id}` и `/rules` доступны в той же светлой теме.

Моушн-дизайн реализован на `framer-motion`: переходы загрузки/анализа/результата,
индикатор этапов, переключатель языка, drag-and-drop, появление событий и шкала
таймлайна. Общие параметры находятся в `src/components/MotionProvider.tsx`.
Учитывается `prefers-reduced-motion`; анимацию схемы обработки можно приостановить.
Схема иллюстрирует процесс, а метрики результата показывают только данные API.
Индикатор ожидания не имитирует процент готовности.

Блок «Проверка правил» показывает отдельный проход модели по фактам: подтверждение,
противоречие или недостаток данных, объяснение и временные отметки каждого факта.
Проверяется также связь действий с одним эпизодом обслуживания. Ограничение числа
проверок, нехватка времени и недоступные ответы показаны явно. При незавершённых
проверках отсутствие совпадений отображается как «Недостаточно данных для вывода».
Самооценка модели не является вероятностью нарушения; решение принимает человек.
Для задач, созданных до этой функции, требуется новый анализ, чтобы получить проверки.
